# DATABASE DESIGN DOCUMENT
## Cloud-Based Notes Sharing Platform (NoteSphere)

**Version:** 1.0  
**Database:** Cloud Firestore (NoSQL Document Store)  
**Authentication:** Firebase Authentication  
**File Storage:** Cloudinary (PDFs only)  
**Backend:** Python Flask  

---

## 1. PURPOSE AND DESIGN GOALS

This document defines the Firestore schema, indexing strategy, data lifecycle, and Cloudinary asset referencing for NoteSphere.

### Key Goals:
- High performance querying by status, semester, subject, and uploader.
- Deterministic identification using stable Firestore document IDs (`noteId`).
- Tight synchronization between Firestore metadata and Cloudinary assets.
- Server-enforced role-based access control and moderation states.
- Absolute prevention of orphaned files or unauthorized access to unapproved assets.

### Fundamental Architecture Rule:
- **Cloudinary** stores the actual PDF binaries.
- **Cloud Firestore** stores note metadata, subject taxonomy, and Cloudinary asset references.
- **Firebase Authentication** manages user identity.
- **Python Flask** validates requests, verifies ID tokens, and enforces access control.
- **Firebase Storage is strictly NOT used.**

## 2. COLLECTIONS OVERVIEW

```text
Firestore Root
├── users/              (User profiles and role assignments)
│   └── {firebaseUid}
├── notes/              (Academic note metadata, moderation state, Cloudinary references)

├── subjects/           (Academic subjects categorized by department and semester)
│   └── {subjectId}

```

## 3. COLLECTION SPECIFICATIONS

### 3.1 `users` Collection
**Path:** `users/{firebaseUid}`  
**Key:** Firebase Authentication UID.

| Field | Type | Description |
|---|---|---|
| `uid` | string | Firebase Auth UID |
| `displayName` | string | Full name of the user |
| `email` | string | User email address |
| `role` | string | `"student"` or `"admin"` (Set strictly by server-side logic) |
| `departmentId` | string \| null | Department identifier (e.g., `"computer-engineering"`) |
| `createdAt` | timestamp | Server timestamp when profile was created |
| `updatedAt` | timestamp | Server timestamp when profile was updated |
| `isActive` | boolean | Account status flag (default `true`) |

### 3.2 `subjects` Collection
**Path:** `subjects/{subjectId}`  
**Key:** Canonical slug or generated ID (e.g., `"dbms-sem4"` or Firestore auto-ID).

| Field | Type | Description |
|---|---|---|
| `name` | string | Display name (e.g., `"Database Management Systems"`) |
| `normalizedName`| string | Lowercase name for matching (e.g., `"database management systems"`) |
| `subjectCode` | string \| null | Course/subject code (e.g., `"DBMS"`, `"CS501"`) |
| `departmentId` | string | Department reference (e.g., `"computer-engineering"`) |
| `semester` | number | Academic semester (e.g., `1` through `8`) |
| `courseName` | string \| null | Degree program (e.g., `"B.Tech Computer Engineering"`) |
| `isActive` | boolean | Whether subject appears in active dropdowns (`true`) |
| `createdAt` | timestamp | Server creation timestamp |
| `updatedAt` | timestamp | Server update timestamp |

### 3.3 `notes` Collection
**Path:** `notes/{noteId}`  
**Key:** Canonical note ID generated by Firestore or backend UUID.

| Field | Type | Description |
|---|---|---|
| **Identity & Content** | | |
| `title` | string | Title of the note (max 150 chars) |
| `normalizedTitle` | string | Lowercase title for prefix/substring filtering |
| `description` | string | Overview or syllabus topics covered |
| `subjectId` | string | Reference to `subjects` document |
| `subjectName` | string | Denormalized subject name snapshot for efficient rendering |
| `semester` | number | Target semester (e.g., `1` to `8`) |
| `departmentId` | string | Target department |
| `courseName` | string \| null | Course title snapshot |
| `tags` | array\<string\> | Search keywords / unit labels (e.g. `["Unit 1", "SQL"]`) |
| **Uploader Attribution** | | |
| `uploadedBy` | string | Firebase UID of student who submitted the note |
| `uploaderName` | string \| null | Display name of uploader at time of submission |
| **File & Cloudinary Metadata** | | |
| `originalFileName`| string | User's original file name (e.g., `"dbms_notes.pdf"`) |
| `fileFormat` | string | Always `"pdf"` |
| `mimeType` | string | Always `"application/pdf"` |
| `fileSizeBytes` | number | Size in bytes (max 10 MB = 10,485,760 bytes) |
| `cloudinary` | map | Structured Cloudinary asset reference |
| `cloudinary.publicId` | string | Public identifier (e.g., `"study-notes/note_<noteId>"`) |
| `cloudinary.resourceType`| string | Cloudinary resource type (`"image"` or `"raw"`) |
| `cloudinary.deliveryType`| string | Delivery type (`"authenticated"` or `"upload"`) |
| `cloudinary.version` | number \| null | Cloudinary version number |
| `cloudinary.secureUrl` | string \| null | Secure URL (only if public delivery approved) |
| `cloudinary.assetId` | string \| null | Cloudinary internal asset ID |
| **Moderation State** | | |
| `status` | string | `"pending"` \| `"approved"` \| `"rejected"` \| `"deleted"` |
| `rejectionReason`| string \| null | Admin notes if rejected |
| `reviewedBy` | string \| null | Firebase UID of reviewing administrator |
| `reviewedAt` | timestamp \| null | Timestamp of approval or rejection |
| **Counters & Timestamps** | | |
| `downloadCount` | number | Number of authorized downloads (starts at 0) |
| `createdAt` | timestamp | Submission timestamp (server-generated) |
| `updatedAt` | timestamp | Last metadata modification timestamp |
| `approvedAt` | timestamp \| null | Timestamp when status transitioned to approved |

## 4. DETERMINISTIC ASSET RETRIEVAL & LIFECYCLE WORKFLOWS

### 4.1 Upload & Atomicity Workflow
```text
Client (Student)                     Flask Backend                    Cloudinary                  Cloud Firestore
      |                                    |                               |                             |
      |-- POST /api/notes (PDF+Form) ----->|                               |                             |
      |                                    |-- Validate PDF magic bytes    |                             |
      |                                    |-- Generate noteId             |                             |
      |                                    |-- Upload PDF (publicId) ----->|                             |
      |                                    |<-- publicId, format, size ----|                             |
      |                                    |                                                             |
      |                                    |-- Write notes/{noteId} (status: pending) ------------------>|
      |                                    |   [IF WRITE FAILS]:                                         |
      |                                    |   |-- Destroy asset (rollback) -> Cloudinary                |
      |                                    |   \-- Return 500 Error to Client                            |
      |<-- 201 Created (noteId, pending) --|                                                             |
```

### 4.2 Authorized Download Workflow
```text
Client (User)                        Flask Backend                         Cloud Firestore              Cloudinary
      |                                    |                                      |                         |
      |-- GET /api/notes/{id}/download --->|                                      |                         |
      |                                    |-- Get notes/{id} ------------------->|                         |
      |                                    |<-- Return Note Document -------------|                         |
      |                                    |                                                                |
      |                                    |-- Verify status == "approved"                                  |
      |                                    |   [IF NOT APPROVED]: Return 403 Forbidden                      |
      |                                    |                                                                |
      |                                    |-- Increment downloadCount ---------->|                         |
      |                                    |-- Generate signed delivery URL / controlled redirect --------->|
      |<-- Redirect (302) or Download URL -|
```

### 4.3 Admin Deletion Workflow
1. Admin requests `DELETE /api/admin/notes/{noteId}`.
2. Flask verifies admin role via token and Firestore `users/{uid}` record.
3. Flask fetches `notes/{noteId}` to retrieve `cloudinary.publicId`.
4. Flask issues `cloudinary.uploader.destroy(publicId, resource_type=resourceType)`.
5. Flask deletes (or marks `status = "deleted"`) the Firestore document `notes/{noteId}`.
6. Returns 200 OK.

## 5. QUERY AND INDEXING PLAN

| Query Pattern | Collection | Filters | Sort Order |
|---|---|---|---|
| **Public Recent Notes** | `notes` | `status == "approved"` | `createdAt DESC` |
| **Filter by Subject** | `notes` | `status == "approved" AND subjectId == X` | `createdAt DESC` |
| **Filter by Semester** | `notes` | `status == "approved" AND semester == Y` | `createdAt DESC` |
| **Filter by Both** | `notes` | `status == "approved" AND subjectId == X AND semester == Y` | `createdAt DESC` |
| **Sort by Downloads** | `notes` | `status == "approved"` | `downloadCount DESC, createdAt DESC` |
| **My Uploads** | `notes` | `uploadedBy == <userUid>` | `createdAt DESC` |
| **Admin Moderation** | `notes` | `status == "pending"` | `createdAt ASC` |
| **Admin History** | `notes` | `status IN ["approved", "rejected"]` | `reviewedAt DESC` |

## 6. VALIDATION RULES MATRIX

- **Title**: Required, 3–150 characters, trimmed of leading/trailing spaces.
- **Description**: Optional, max 1000 characters.
- **Semester**: Required, integer in range `1` to `8`.
- **Subject ID**: Required, must exist and be active in `subjects` collection.
- **PDF Binary**: Magic bytes must start with `%PDF-` (`0x25 0x50 0x44 0x46 0x2D`). Max size: 10,485,760 bytes (10 MB).
- **Status Transitions**:
  - Creation: Always forced to `"pending"`.
  - Moderation: Only verified admins can transition to `"approved"` or `"rejected"`.
